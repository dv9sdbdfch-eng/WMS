# Store WMS — аналіз робочих процесів

Дата: 09.11.2026, версія v1.19.0.

**Як рахували.** Кроки порахувано за кодом екранів і знімками 1366×768 (найкоротший шлях
досвідченого користувача з клавіатурою/сканером). Це **оцінка, а не замір часу**: на реальному
ПК ніхто не працював із секундоміром, тому секунд і хвилин тут немає. «Дія» = клік, клавіша
(F2, Enter) або скан. «Введення» = поле, яке людина набирає/сканує. N — кількість рядків
(матеріалів) у документі.

Номери рекомендацій (R-…) — з [дорожньої карти](WMS_DEVELOPMENT_ROADMAP.md).

## Детально по сценаріях

### 1–3. Знайти матеріал, запас, комірку ✅ добре

**Зараз:** Ctrl+K → скан/код → Enter. При точному збігу — зелена смужка з товаром, F2/F3/F4 діють
для нього (v1.15.1). Materials показує On Hand, Available, Bin («A02B01 +1»).
**Проблема:** коли комірок кілька, видно лише першу. **Рекомендація:** tooltip на колонці Bin з
повним розподілом (A02B01: 60, B01B01: 30). Повторних введень немає.

### 4. Прийняти поставку постачальника

**Зараз (F2):** 1) F2 · 2) постачальник (набір + Enter) · 3) Purchase order (вибір → рядки
заповнюються залишком) · 4) № накладної · 5) дата (за замовчуванням сьогодні) · 6) Attach file →
файловий діалог · 7) змінити кількості, що прийшли інакше · 8) Post delivery → підтвердження.
Пошкоджене: окремо «Report problem…» і окремо переміщення в карантин.
**Ризики помилок:** забули скан (є попередження ✅), подвійна накладна (є перевірка ✅),
пошкоджене оприбутковане у звичайну комірку (⚠️).
**Рекомендовано:** скан номера PO в полі Purchase order (P2); колонка «Damaged qty» в рядку →
система сама кладе цю кількість у карантинну комірку і створює проблему поставки (P2, R-W1).
**Економія:** 1 документ і 1 переміщення на кожну пошкоджену позицію.

### 5. Видати матеріали на проєкт

**Зараз (F3):** 1) F3 · 2) проєкт (скан номера) · на кожен рядок: 3) товар (скан) · 4) кількість ·
(комірка автоматично) · 5) Post → підтвердження → «Open issue note?».
**Повторне введення:** програма вже знає Required, Reserved і Remaining проєкту, але людина
вводить кожну позицію з паперу/Excel. Для 40 позицій — ≈80 введень.
**Рекомендовано:** кнопка «Load from project…» → вибір: *усі зарезервовані* / *Remaining
юніта/рівня/блоку* / *з picking list* → рядки підставлені, людина лише правит кількості.
Правила обліку **не змінюються**: проведення так само йде через `GoodsOutService.post`.
**Економія:** ≈N·2 введення → правки лише відхилень.

### 6. Зарезервувати матеріали проєкту

**Зараз:** Projects → Reservations → Reserve stock… → товар, проєкт, кількість, дата → Save.
**Повторити на кожен матеріал.**
**Рекомендовано:** у Projects/Planning: «Reserve remaining…» для проєкту, блоку, рівня або юніта →
таблиця попереднього перегляду: потрібно / доступно / буде зарезервовано / не вистачає → одна
кнопка. Резервується `min(To Allocate, Available)`; нестача → у «To Purchase». Кожен резерв
створюється існуючим `ReservationService.reserve` (той самий захист від перерезерву) в **одній
транзакції**. **Економія:** N діалогів → 1 перегляд.

### 7. Повернути невикористане

**Зараз:** MORE ▸ Returns → Return from site → проєкт → рядки (товар, кількість, комірка, стан) → Post.
**Рекомендовано:** з проєкту «Return to store…» — рядки з Net Issued > 0, людина ставить
кількості; DAMAGED автоматично у карантин (R-A1). **Економія:** вибір товарів і перевірка «скільки
видавали».

### 8. Переміщення між комірками

**Зараз:** F4 → товар → з → куди → кількість → Ctrl+S. На кожен товар — нове вікно.
**Рекомендовано:** (а) кілька рядків в одному вікні (скан товар → кількість, комірки «з/куди»
спільні); (б) «Move whole bin…» з картки комірки. Кожен рядок — окремий `StockTransfer` (схема не
змінюється), але одна транзакція. **Економія:** N вікон → 1.

### 9. Невидані потреби проєкту

**Зараз:** Materials → Project: X → колонка Remaining → сортування. Або Projects → Material Demand.
**Рекомендовано:** Planning view (див. [UI/UX](WMS_UI_UX_IMPROVEMENTS.md), розділ 5) і лічильник
«Projects short of material» на Dashboard.

### 10. Підготувати доставку на об'єкт

**Зараз:** у програмі немає. Адреса, контакт, телефон проєкту **вже є** в записі проєкту, але
лист кур'єру пишеться вручну.
**Рекомендовано:** «Delivery booking» (вихідна доставка) з проєкту/Goods Out: адреса збору (склад
за замовчуванням), адреса доставки і контакт з проєкту, дата і слот, кур'єр, тип авто, палети,
вага (сума з ваги матеріалів, якщо заповнена), статус Booked → Collected → Delivered, POD (фото/
підпис-скан). Кнопка «Email courier» відкриває **чернетку** листа в Outlook (`mailto:`), нічого не
відправляється саме. Повторне введення адреси/контакту → 0.

### 11. Picking list

**Зараз:** немає. Друкується лише Issue note **після** проведення.
**Рекомендовано:** з проєкту/юніта/рівня або з чернетки Goods Out → PDF «Picking list»: товар,
кількість, **комірки в порядку обходу** (за кодом комірки), місце для відмітки. Picking list не
змінює запас. Потім «Issue from picking list» → Goods Out з тими самими рядками.

### 12–13. Excel

Експорт поточного виду = екрану ✅. Імпорт Project Material List — майстер з профілями ✅.
**Рекомендовано (R-P4):** перед застосуванням показувати «Required зміниться: +12 позицій,
−3 позиції, 5 кількостей», і попереджати, якщо нове Required менше вже виданого.

### 14. Прострочені PO ✅

1 клік з Dashboard. Додати: щоденне нагадування при вході (R-F2) і лист-нагадування постачальнику
як чернетку (P3).

### 15. Інвентаризація

**Зараз:** New count → локація → вводити Counted у таблицю (знайти рядок очима) → Save → Submit →
Approve.
**Рекомендовано:** поле «Scan» над таблицею: скан комірки → фільтр рядків цієї комірки; скан
товару → курсор у його Counted; скан незнайомого товару → «Add item found». План циклічних
підрахунків (наприклад, щотижня N комірок з найбільшим обігом) — P3.

постачальнику. Будь-яка автоматика, що змінює запас, лише **готує документ**, а проводить його людина.
